# codex-resume

Windows 本地 Codex 桌面续跑助手：选择原会话，等待真实额度恢复，再发送你确认的续跑提示词。
这是独立项目，当前不对接 notification 或其他工作区项目（用户 2026-10-23 确认）。
要求 Windows、已打开并登录的 Codex 桌面 App、Node.js 24+、pnpm 11.20。
桌面采用 Electron 45、Vue 3、TypeScript、Pinia、Element Plus 与 SQLite；保留原有 CLI 验证工具。

## 安装与检查

```powershell
pnpm --dir codex-resume install
pnpm --dir codex-resume build
pnpm --dir codex-resume test
pnpm --dir codex-resume dev
```

以下命令均以 `codex-resume` 为工作目录；也可在项目根目录给 pnpm 添加 `--dir codex-resume`。
`build` 执行 TypeScript 与 Vue 类型检查，生成 `out/`；`start` 运行生产桌面壳。CLI 使用 `pnpm cli help`，由 Node.js 直接运行可擦除类型的 `.ts` 文件。

## 桌面应用

1. 保持 Codex App 打开并登录，启动 `pnpm --dir codex-resume dev`，或构建后 `pnpm --dir codex-resume start`。
2. 在“运行总览”查看五小时与每周剩余额度、预计恢复时间及独立的监控进程心跳。
3. 打开“托管任务”，从最近 50 条及置顶的本机会话选择目标，确认续跑提示词、次数上限及自动发送授权。
4. 仅真实服务端额度错误触发等待；服务端确认两个窗口均可用、账号和目标轮次未变化后，向原会话投递一次并核对回执。

自动发现唯一的 Codex 管道，并从本机 `session_index.jsonl` 尾部读取调用会话 ID。存在多个管道时，可在设置中指定管道；更换连接参数前须暂停全部托管。不读取认证文件。

次数范围 1–20，默认 3；自动续跑再次遇到额度错误时继续等待下一轮恢复。加入时实时检查当前 Goal 和最新轮次；没有未结束 Goal 且最新轮次正常结束时，提示“该任务已经完成，无法加入托管列表”。已托管任务满足同一完成条件后自动移除，事件、任务名和发送尝试保留。

“暂停托管”只停止之后的投递，不中断 Codex，也无法撤回已提交的消息。发送不确定时仅核对回执；成功提交后三分钟仍未找到对应新轮次也转为待核对。审批、普通失败、人工恢复、主动中断及账号变化会停止托管。

提交后尚未匹配到唯一标记的新轮次时显示“等待投递回执”；匹配后显示“已续跑，等待完成”。后者表示该轮已被接收，仍需等待轮次结束。存在未结束 Goal 时，单轮完成后继续观察；Goal 主动暂停、受阻或自身预算耗尽时停止投递并保留记录。Goal 清除且最新轮次正常完成才移除；清除后仍在运行或失败时保留任务，Goal 身份变化会停止旧授权。多轮 Goal 仍受累计续跑次数上限约束。

Goal 元数据通过只读连接从 `CODEX_HOME`（默认 `~/.codex`）下的 `goals_1.sqlite` 读取，仅选择指定会话的 Goal 身份和状态，不读取 objective、不创建或修改源库。缺库、结构不兼容或读取失败时保守停止相关创建／投递／完成判断；不需要订阅历史 Goal 完成事件。旧版 completed 记录先重新校验，未结束 Goal 保留为暂停记录。CLI 原跟随模式保持原规则。

应用设置卡片依次为：额度恢复检查、监控与桌面、字号与页面外观、本机数据。

默认关闭窗口保留托盘；双击托盘重新打开，托盘菜单“退出并停止监控”结束助手。休眠、关机或退出期间不检查；重启后重新读取真实状态，不根据时间推算恢复。没有自动安装服务或开机启动。

### 管理功能（REQ-20261106-08 的 11 项与独立扩展，源码交付）

| 功能 | 使用入口 |
|---|---|
| 为什么没续跑 | 总览或托管详情 → 运行只读自检，逐项显示阻断／未知／未检查及建议 |
| 生命周期时间线 | 托管详情或历史归档 → 时间线，区分提交、回执、轮次结束与当前任务完成 |
| 历史归档 | 侧栏历史归档；完成与用户移除分别记录，旧缺失字段明确标未知 |
| 只读刷新 | 顶部“刷新状态（只读）”；“立即检查”可能推进已授权任务；本机刷新仅读数据库 |
| 连接与兼容性自检 | 总览或托管详情，独立只读连接检查工具、双额度、账号、Goal 与本地库 |
| 提示词模板 | 侧栏提示词模板：默认、增删改与预览；创建托管复制正文并确认 |
| 暂停编辑 | 托管列表 → 暂停后编辑配置；保存仍暂停，继续时预览并确认当前修订 |
| 优先级与队列 | 创建／暂停编辑设高普通低；列表同级上移下移；设置启用并发 1–20，默认关闭 |
| 仅观察 | 创建／暂停编辑选择仅观察，后台意图前强制阻断，恢复提醒持久化去重 |
| 有效期与时段 | 创建／暂停编辑；默认全天无截止，本机时区、跨午夜、开始含结束不含 |
| 全历史检索与导出 | 历史归档 → 检索历史日志，任务／日期／类型／异常原因，50 条分页、全部匹配 JSONL |
| 重置卡（独立需求） | 侧栏重置卡：只读真实卡片明细，为指定卡预约一次性兑换；执行前复核账号与卡片，结果不确定保留原请求 ID |

只读诊断结果与调度缓存隔离，不改变自动额度计划或发送计数；后台原有监控独立继续。数据读取时间和过期状态单独显示，通过只代表读取时间点。

发送意图与槽位同事务保存。发送中、待回执及匹配后仍运行占槽；暂停、到期、Goal 异常、超时或重启不会释放。只有确定派发前取消或读到对应轮次结束才释放。未落定投递禁止编辑、模式切换、删除重建与重新授权，只核对不补发。高优先级不抢占，降低限制不取消已提交轮次。仅计算本助手投递，不计算人工或 Goal 自主后续轮次。

时段外仍检查状态和回执；到期停止后续投递，不标为完成。仅观察时段外的恢复提示只在应用内显示，允许时段重新核验后才发系统通知，到期不再产生提醒。模板修改不追改已有任务；修订事件仅记录变更字段，未来意图关联修订号，累计次数不重置。

数据库使用版本 4 事务迁移，保留旧四表、旧提示词、授权和累计次数；旧任务自动续跑、全天无截止，队列默认关闭。新增表 archives / templates / revisions / reset_appointments，attempts 独立保存修订与槽位，重置卡预约持久化唯一幂等键。重复打开幂等，失败回滚，未知高版本拒绝降级；旧版程序不应再打开升级后的库。旧已删除任务只能从残存事件恢复不完整历史，不补造结果，历史页不恢复旧授权。CLI 三种模式与默认规则保持。

范围导出在独立只读 SQLite 快照内按 100 条批次读取，旧到新写入临时文件，成功后改名并显示条数；保存对话框取消不创建结果。最近 150 条预览和导出入口仍保留。日期筛选使用本机时区，结束时间不包含；内部仍保存时间戳。分页使用固定最大 ID 与稳定 ID 游标。

本轮不打包、不覆盖 release、不部署；运行中的旧实例不会自动获得新菜单，未修改其数据库或进程。实际验证记录见 VALIDATION。

### 额度恢复检查

“应用设置 → 额度恢复检查”统一使用定期检查，默认每 10 分钟查询一次。与下方监控参数一起点击“保存设置”后生效，并保存在 SQLite，重启保留。

| 配置 | 默认与范围 | 行为 |
|---|---|---|
| 额度检查间隔 | 默认 600 秒（10 分钟），10–3600 秒 | 额度耗尽、可用或未知时均按此间隔查询；预计恢复时间仅作展示 |
| 任务检查间隔 | 默认 15 秒，10–300 秒 | 独立刷新会话列表和托管状态，不绕过额度策略 |

总览额度查询与任务检查已拆开；两次定期检查之间，总览保留上次额度及读取时间。同一检查中的任务共用刚查询的额度，账号、窗口、原停止轮次和发送授权仍逐项核对。设置和使用说明顶部显示下次额度查询时间。

启动／重启立即查询；后台每两秒判断是否到期，休眠错过检查后恢复运行时补查一次，退出期间不执行。查询失败按同一间隔重试；顶部“立即检查”可提前查询并推进已授权任务。预计时间和本地倒计时不能代替服务端真实可用证明。旧 CLI 保持原有独立轮询规则。

旧预计恢复模式迁移为每 10 分钟检查；已有固定间隔保留自定义值。恢复后缓冲和每日额外检查已移除，旧配置读取时忽略这些字段，保存设置后仅保留检查间隔。

### 字号与页面外观

“应用设置 → 字号与页面外观”可以分别调整页面标题、分区标题、正文、辅助文字和导航字号，并设置行高、系统/微软雅黑字体、舒适/紧凑密度及文字对比度。主题配色提供 10 种纯色和 10 种渐变色卡，默认保留当前青绿主题；点击色卡即时预览，主要按钮、选中导航与侧栏同步变化，焦点使用对应主题色。默认正文为 16px，辅助文字为 13px；总览、任务、日志、说明、弹层与表单共用同一套语义字号。

| 配置 | 默认 | 可调范围 |
|---|---|---|
| 页面标题 | 28px | 24–40px |
| 分区标题 | 18px | 16–30px |
| 正文 | 16px | 12–24px |
| 辅助文字 | 13px | 11–18px |
| 导航 | 15px | 13–20px |
| 正文行高 | 1.7 倍 | 1.4–2.2 倍 |

支持“标准阅读 / 大字阅读 / 紧凑显示”预设和即时预览，切换阅读预设保留当前主题。“保存外观”后全局应用并写入 SQLite，重启保留；离开设置页撤销未保存预览，“恢复默认”还原青绿配色及默认字号，也需保存才长期生效。外观与下方监控表单分别保存，互不覆盖未提交的修改。升级旧配置时自动补齐外观默认值，保留旧主题选择、原有监控参数和托管状态。

字号采用页面 CSS 像素，实际显示大小同时受 Windows 缩放影响；主题色作用于主要交互元素，正常、警告等状态色保持语义。修改外观不需要重启，也不改变额度、连接或自动续跑规则。

### 应用图标

统一源图是 `resources/icons/logo.png`，当前为 256×256 透明 PNG，由用户提供的 200×200 图案等比放大。侧栏、说明书封面、窗口、托盘、通知和 Windows 程序/安装包共用它；替换此文件后重新构建、打包即可更新，不需要维护多份源图。Windows 打包要求源图宽高均不小于 256 像素；替换时请使用至少 256×256 的正方形 PNG，否则 `pack / dist` 会报 `Icon must be at least 256x256 pixels`。放大可满足打包尺寸要求，但不会增加原图细节。

界面由 Vite 打包图片；主进程通过 `?asset` 定位源图，读取为 NativeImage，窗口采用 256×256 表示、托盘采用 32×32 表示。该目录属于 electron-vite 主进程默认 publicDir，`?asset` 不会自动把文件复制进 out，所以 `build.files` 显式包含 `resources/icons/logo.png`，确保安装后仍可读取。

Windows 使用 `build.win.icon` 指向同一 PNG，electron-builder 自动生成 ICO；NSIS 安装和卸载图标默认继承该应用图标。`signAndEditExecutable: true` 启用 EXE 图标及版本资源写入，`signExecutable: false` 保持不做代码签名。资源编辑和签名是两个独立步骤，不能为了跳过签名而再次关闭资源编辑。

### 应用内使用说明

侧栏“使用说明”提供离线说明书，共 13 章，支持全文关键词筛选、目录跳转和上一章／下一章。查找目录默认吸附阅读区左缘，悬浮时覆盖正文。内容包括数据来源与已有登录态、五小时/周额度判断、独立额度策略与本地快照更新时机、自动续跑和回执核对、托盘与重启、本地隐私、设置、日志及排查。顶部显示任务检查间隔、额度策略、最近额度读取和下次查询时间。

阅读和搜索本身不调用操作命令；已有后台托管仍继续。顶部“立即检查”会推进完整检查，条件满足时可能触发已授权任务的续跑；界面约两秒更新快照不代表两秒查询一次额度。详细内容维护在 `renderer/src/manual.ts`，通过 `ManualPage.vue` 展示，随安装包提供。

更新后需从托盘明确退出旧进程再启动新版，旧进程不会自动出现新功能。为了保留正在运行的旧版，此前 0.2.4 包输出在 `release/0.2.4/`；可用下面的构建后命令生成同类独立目录：

```powershell
pnpm exec electron-builder --win nsis --x64 --config.directories.output=release/0.2.4
```

### 进程与数据

“应用设置 → 本机数据”直接预览最近 150 条事件，最新在前，随后台快照自动更新。“刷新数据”重新读取本机数据库，不查询额度或推进托管；顶部“立即检查”仍执行完整监控检查。

预览和 JSONL 导出共用格式：时间按本机时区显示为 `YYYY-MM-DD HH:mm:ss`，包括事件时间、下次检查时间和额度窗口重置时间。事件同时包含 `taskId` 与 `taskName`，新事件保留记录时的任务名，移除托管后仍可查看；旧数据升级时从仍存在的托管记录补齐名称，无法恢复的历史任务名及应用级事件使用 `null`。

“导出最近事件”在确认保存位置后重新读取本机数据，以 JSONL 每行一条、从旧到新写出最近 150 条事件；预览使用便于阅读的 JSON 数组。导出仅包含事件，不是完整数据库备份。SQLite 内部仍使用原始时间戳进行调度。

0.2.4 增加额度排查日志：`thread_state_observed` 记录会话状态、最新轮次、最多 1000 字符的服务端错误摘要及 `usageLimitDetected`，相同状态跨周期和重启去重；`quota_checked` 保留当前判断依据、窗口与限制标志，不含账号标识；`resume_preflight_passed`、`resume_receipt_matched` 分别记录最终发送检查和标记匹配。普通停止事件也携带当时状态；不记录聊天正文或完整工具输出。出现问题后及时导出最近事件，较早记录仍保留在本机 SQLite 中。

2026-11-06 的诊断版本 3 保持查询及续跑规则不变：相同额度快照按十分钟分段合并，保留 `checkCount`、`firstCheckedAt`、`lastCheckedAt`，跨重启累计，额度或观察依据变化立即新增，旧版事件不回写。`nextCheckAt` / `nextQuotaCheckAt` 记录本次查询后实际安排的桌面检查时间，`gateSuggestedCheckAt` 只保留通用门禁建议；合并记录的事件时间仍为首次检查时间。预览和导出均展示上述时间与计数。

`systemError` 仅表示会话出错，是否等待额度取决于最新失败轮次的服务端错误。历史错误可能缺少 `codexErrorInfo`，已兼容 `You’ve hit your usage limit` 的 Unicode 弯引号。Goal 自身预算耗尽不触发额度续跑；本助手核验一次投递轮次的完成，不能据此判断整个 Goal 完成，也不修改 Goal 生命周期。

此前修复独立打包到 `release/0.2.4/win-unpacked/Codex Resume.exe`，保留运行中的旧版。请从托盘退出旧版后启动该文件；已停止的旧托管不会自动重新开启，需要按实际工作需求重新托管。

- Electron 主进程管理窗口、托盘、通知、单实例和受限 IPC；沙箱与上下文隔离开启。
- 独立 `utilityProcess` 持有桌面管道、顺序调度和 SQLite，每两秒报告心跳；任务检查默认 15 秒，额度按独立策略调度。
- Vue 界面仅通过类型化 `contextBridge` 使用固定操作，不直接访问文件、数据库或管道。
- `%APPDATA%\codex-resume\resume.sqlite` 保存 `tasks / attempts / events / settings / archives / templates / revisions`，WAL + FULL 同步，事务提交发送意图后才发送。
- 账号只保存 SHA-256 指纹，界面不接收原始账号标识或聊天正文；提示词和事件保存在本机。
- CLI 与桌面共用 `%APPDATA%\codex-resume\locks` 的目标锁；`CODEX_RESUME_LOCK_DIR` 可显式覆盖。
- 旧 `var/*.json` 验证作业不自动导入或开启；监控进程意外退出最多重启三次，发送中作业转为待核对。

### 桌面验证与打包

```powershell
pnpm --dir codex-resume test:workflow
pnpm --dir codex-resume test:desktop
pnpm --dir codex-resume pack
pnpm --dir codex-resume dist
```

`test:workflow` 使用隔离的假命名管道和数据库，经真实界面验证确认托管、等待、暂停、恢复、单次发送及回执，不调用真实账号。`test:desktop` 要求当前 Codex 可连接，验证真实只读接入、界面、SQLite、监控进程崩溃重启和托盘，不创建托管、不发送。**两种桌面测试须顺序运行**，避免假管道影响唯一发现。

`pack` 默认输出 `release/win-unpacked/Codex Resume.exe`，无需系统 Node.js，须保留整个目录；`dist` 默认在 `release/` 生成 NSIS 安装包。0.2.4 本次使用上述独立输出目录，未覆盖运行中的旧版，仅生成目录包，未生成 NSIS 安装包。首版未配置代码签名或自动更新。桌面冒烟截图与报告自 0.2.1 起按版本保存在 `var/desktop-smoke/<版本>/`；历史 fixture 报告仍在父目录。实际验证边界见 [VALIDATION.md](VALIDATION.md)。

Electron 首次启动会下载运行时，可提前运行 `pnpm --dir codex-resume install:electron`。启动脚本移除终端继承的 `ELECTRON_RUN_AS_NODE`，确保打开 GUI。

## CLI 三种验证模式

| 模式 | 额度与错误 | 发送及回执 | 结论边界 |
|---|---|---|---|
| simulation | 内存信号、虚拟时钟 | 内存目标 | 只证明状态机及边界行为 |
| hybrid | 注入受限错误及短等待窗口，到时读取真实额度 | 真实桌面原会话 | 证明等待、真实额度复查、单次发送及回执链路，不证明真实额度曾耗尽 |
| live | 桌面返回的真实错误与额度 | 真实桌面原会话 | 错误、受限快照、恢复快照和回执齐全，才记录真实闭环成功 |

```powershell
pnpm cli simulate --job var/demo.json
pnpm cli inspect --caller <本次授权会话ID>
pnpm cli hybrid --caller <本次授权会话ID> --target <已完成测试会话ID> --delay-ms 15000 --poll-ms 1000 --max-ms 90000
```

混合验证只能选择已完成且空闲的其他会话；它只要求模型回复唯一标记，不执行工具或修改旧项目。
混合验证的窗口和错误明确标注为 `injected`，证据文件不会将其记为真实恢复。
时间到了但真实五小时或每周额度仍耗尽时，程序继续等待，不发送。

## 登记与运行真实验证

```powershell
pnpm cli arm --caller <本次授权会话ID> --target <指定目标会话ID> --job var/my-task.json
pnpm cli run --job var/my-task.json --poll-ms 30000 --max-ms 21600000
pnpm cli status --job var/my-task.json
```

`arm` 仅登记，不发送消息；`run` 启动独立于模型的监控，最多运行指定时间。
登记时添加 `--follow-session` 可在正常结束后继续只读观察同一聊天，等待后续自然限额事件；不会续跑已完成轮次。
真实模式仅在指定会话最新一轮出现明确的服务端 `UsageLimitExceeded` 错误后等待并续跑。
普通完成、主动中断、非额度失败、人工恢复、目标变化、审批或输入等待不会自动触发续跑。
默认续跑同样只回复标记，以验证真实跨窗口链路。需要继续业务工作时，登记时显式添加 `--prompt-file <中文提示词文件>`。
业务提示词由用户定义，程序不会自行扩大任务目标；本项目只核验续跑轮次完成，不等同于业务总目标完成。

状态保存在 `var/*.json`，事件记录在同名 `.events.jsonl`。不要手工修改运行中作业的目标、提示词或状态。
同一目标在本项目中只允许一个监控实例；即便作业文件名不同也持有目标锁。
正常停止会释放锁；进程被强制终止后，确认原进程已退出再运行：

```powershell
pnpm cli unlock --job var/my-task.json
pnpm cli run --job var/my-task.json
```

发送前先持久化意图；发送超时或中途崩溃时不会盲目补发：

```powershell
pnpm cli reconcile --job var/my-task.json
pnpm cli status --job var/my-task.json
```

`reconcile` 仅核对投递标记和原会话回执，不会补发。仍不确定时保留 `send_uncertain`，交由用户核对。

## 当前限制

- 接口来自已验证的桌面内部命名管道，升级可能变化；程序会发现管道并核对工具目录和必要参数。
- 不读取 `auth.json`，不购买积分，也不切换账号或 API 计费。重置卡通过官方 App Server 只使用用户明确预约的指定卡片，不自动替换其他卡；未授权不消费真实卡。
- 缺失额度值按未知处理；同时检查五小时和每周窗口，恢复时间之后仍需真实服务端复查。
- 多个桌面管道需要用户显式指定 `--pipe`；连接关闭后只读请求允许重新发现和重连。
- 当前使用 `read_thread` 轮询，不依赖此前外部调用失败的 `wait_threads`。
- 发送前的最后检查与桌面接收之间仍有极短的人工并发窗口；内部接口没有原子条件发送承诺。
- 支持等待状态保存及重启，但不自动安装系统服务或开机启动；桌面 App 和监控进程都需要运行。
- 真实额度未耗尽时，不人为烧额度来制造验证条件；最新实际结果见 `VALIDATION.md`。
