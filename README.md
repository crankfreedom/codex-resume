# codex-resume

Windows 本地 Codex 桌面续跑助手：选择原会话，等待真实额度恢复，再发送你确认的续跑提示词。
这是独立项目，当前不对接 notification 或其他工作区项目（用户 2026-10-23 确认）。
要求 Windows、已打开并登录的 Codex 桌面 App、Node.js 24+、pnpm 11.20。
桌面采用 Electron 45、Vue 3、TypeScript、Pinia、Element Plus 与 SQLite；保留原有 CLI 验证工具。

## 安装与检查

```powershell
pnpm --dir codex-resume install
pnpm --dir codex-resume build
pnpm --dir codex-resume test
pnpm --dir codex-resume dev
```

以下命令均以 `codex-resume` 为工作目录；也可在项目根目录给 pnpm 添加 `--dir codex-resume`。
`build` 执行 TypeScript 与 Vue 类型检查，生成 `out/`；`start` 运行生产桌面壳。CLI 使用 `pnpm cli help`，由 Node.js 直接运行可擦除类型的 `.ts` 文件。

## 桌面应用

1. 保持 Codex App 打开并登录，启动 `pnpm --dir codex-resume dev`，或构建后 `pnpm --dir codex-resume start`。
2. 在“运行总览”查看五小时与每周剩余额度、预计恢复时间及独立的监控进程心跳。
3. 打开“托管任务”，从最近 50 条及置顶的本机会话选择目标，确认续跑提示词、次数上限及自动发送授权。
4. 仅真实服务端额度错误触发等待；服务端确认两个窗口均可用、账号和目标轮次未变化后，向原会话投递一次并核对回执。

自动发现唯一的 Codex 管道，并从本机 `session_index.jsonl` 尾部读取调用会话 ID。存在多个管道时，可在设置中指定管道；更换连接参数前须暂停全部托管。不读取认证文件。

次数范围 1–20，默认 3；自动续跑再次遇到额度错误时继续等待下一轮恢复，续跑轮次正常完成则结束托管。首次托管的空闲会话可以保持只读观察，不会重启已完成轮次。

“暂停托管”只停止之后的投递，不中断 Codex，也无法撤回已提交的消息。发送不确定时仅核对回执；成功提交后三分钟仍未找到对应新轮次也转为待核对。审批、普通失败、人工恢复、主动中断及账号变化会停止托管。

默认关闭窗口保留托盘；双击托盘重新打开，托盘菜单“退出并停止监控”结束助手。休眠、关机或退出期间不检查；重启后重新读取真实状态，不根据时间推算恢复。没有自动安装服务或开机启动。

### 额度恢复检查

“应用设置 → 额度恢复检查”提供两种模式，与下方监控参数一起点击“保存设置”后生效，并保存在 SQLite，重启保留。

| 配置 | 默认与范围 | 行为 |
|---|---|---|
| 查询模式 | 按预计恢复时间 / 固定时间间隔 | 预计时间模式在受限时按服务端时间安排；固定模式始终按配置间隔查询 |
| 恢复后缓冲 | 默认 1 分钟，0–60 分钟 | 两个窗口都耗尽时取较晚恢复时间再加缓冲，例如 3 小时后恢复则等 3 小时 1 分钟 |
| 固定／常规与兜底间隔 | 默认 60 秒，10–3600 秒 | 固定模式始终使用；预计时间模式在额度可用、未知、恢复时间缺失或过期时使用 |
| 每日 00:10 额外检查 | 默认开启，本机时区 | 两种模式均可提前唤醒等待，查询可能发生的重置；不假定服务端必然在零点恢复 |
| 任务检查间隔 | 默认 15 秒，10–300 秒 | 独立刷新会话列表和托管状态，不绕过额度策略 |

总览额度查询与任务检查已拆开；等待预计恢复期间，总览保留上次额度及读取时间，不会仍每 15 秒拉取额度。同一检查中的任务共用刚查询的额度，账号、窗口、原停止轮次和发送授权仍逐项核对。设置和使用说明顶部显示下次额度查询时间。

启动／重启立即查询；后台每两秒判断是否到期，休眠错过 00:10 后恢复运行时补查，退出期间不执行。查询失败按兜底间隔重试；顶部“刷新”可提前查询并推进已授权任务。预计时间、午夜检查和本地倒计时都不能代替服务端真实可用证明。旧 CLI 保持原有独立轮询规则。

### 字号与页面外观

“应用设置”顶部可以分别调整页面标题、分区标题、正文、辅助文字和导航字号，并设置行高、系统/微软雅黑字体、舒适/紧凑密度、青绿/蓝色/紫色主题色及文字对比度。默认正文已提高到 16px，辅助文字为 13px；总览、任务、日志、说明、弹层与表单共用同一套语义字号。

| 配置 | 默认 | 可调范围 |
|---|---|---|
| 页面标题 | 28px | 24–40px |
| 分区标题 | 18px | 16–30px |
| 正文 | 16px | 12–24px |
| 辅助文字 | 13px | 11–18px |
| 导航 | 15px | 13–20px |
| 正文行高 | 1.7 倍 | 1.4–2.2 倍 |

支持“标准阅读 / 大字阅读 / 紧凑显示”预设和即时预览。“保存外观”后全局应用并写入 SQLite，重启保留；离开设置页撤销未保存预览，“恢复默认”也需保存才长期生效。外观与下方监控表单分别保存，互不覆盖未提交的修改。升级旧配置时自动补齐外观默认值，保留原有监控参数和托管状态。

字号采用页面 CSS 像素，实际显示大小同时受 Windows 缩放影响；主题色作用于主要交互元素，正常、警告等状态色保持语义。修改外观不需要重启，也不改变额度、连接或自动续跑规则。

### 应用图标

统一源图是 `resources/icons/logo.png`，当前为用户提供的 1200×1200 透明 PNG。侧栏、说明书封面、窗口、托盘、通知和 Windows 程序/安装包共用它；替换此文件后重新构建、打包即可更新，不需要维护多份源图。

界面由 Vite 打包图片；主进程通过 `?asset` 定位源图，读取为 NativeImage，窗口采用 256×256 表示、托盘采用 32×32 表示。该目录属于 electron-vite 主进程默认 publicDir，`?asset` 不会自动把文件复制进 out，所以 `build.files` 显式包含 `resources/icons/logo.png`，确保安装后仍可读取。

Windows 使用 `build.win.icon` 指向同一 PNG，electron-builder 自动生成 ICO；NSIS 安装和卸载图标默认继承该应用图标。`signAndEditExecutable: true` 启用 EXE 图标及版本资源写入，`signExecutable: false` 保持不做代码签名。资源编辑和签名是两个独立步骤，不能为了跳过签名而再次关闭资源编辑。

### 应用内使用说明

侧栏“使用说明”提供离线说明书，共 13 章，支持全文关键词筛选、目录跳转和上一章／下一章。查找目录默认吸附阅读区左缘，悬浮时覆盖正文。内容包括数据来源与已有登录态、五小时/周额度判断、独立额度策略与本地快照更新时机、自动续跑和回执核对、托盘与重启、本地隐私、设置、日志及排查。顶部显示任务检查间隔、额度策略、最近额度读取和下次查询时间。

阅读和搜索本身不调用操作命令；已有后台托管仍继续。顶部“刷新”会推进完整检查，条件满足时可能触发已授权任务的续跑；界面约两秒更新快照不代表两秒查询一次额度。详细内容维护在 `renderer/src/manual.ts`，通过 `ManualPage.vue` 展示，随安装包提供。

更新后需从托盘明确退出旧进程再启动新版，旧进程不会自动出现新功能。为了保留正在运行的旧版，本次 0.2.3 包输出在 `release/0.2.3/`；可用下面的构建后命令生成同类独立目录：

```powershell
pnpm exec electron-builder --win nsis --x64 --config.directories.output=release/0.2.3
```

### 进程与数据

- Electron 主进程管理窗口、托盘、通知、单实例和受限 IPC；沙箱与上下文隔离开启。
- 独立 `utilityProcess` 持有桌面管道、顺序调度和 SQLite，每两秒报告心跳；任务检查默认 15 秒，额度按独立策略调度。
- Vue 界面仅通过类型化 `contextBridge` 使用固定操作，不直接访问文件、数据库或管道。
- `%APPDATA%\codex-resume\resume.sqlite` 保存 `tasks / attempts / events / settings`，WAL + FULL 同步，事务提交发送意图后才发送。
- 账号只保存 SHA-256 指纹，界面不接收原始账号标识或聊天正文；提示词和事件保存在本机。
- CLI 与桌面共用 `%APPDATA%\codex-resume\locks` 的目标锁；`CODEX_RESUME_LOCK_DIR` 可显式覆盖。
- 旧 `var/*.json` 验证作业不自动导入或开启；监控进程意外退出最多重启三次，发送中作业转为待核对。

### 桌面验证与打包

```powershell
pnpm --dir codex-resume test:workflow
pnpm --dir codex-resume test:desktop
pnpm --dir codex-resume pack
pnpm --dir codex-resume dist
```

`test:workflow` 使用隔离的假命名管道和数据库，经真实界面验证确认托管、等待、暂停、恢复、单次发送及回执，不调用真实账号。`test:desktop` 要求当前 Codex 可连接，验证真实只读接入、界面、SQLite、监控进程崩溃重启和托盘，不创建托管、不发送。**两种桌面测试须顺序运行**，避免假管道影响唯一发现。

`pack` 默认输出 `release/win-unpacked/Codex Resume.exe`，无需系统 Node.js，须保留整个目录；`dist` 默认在 `release/` 生成 NSIS 安装包。0.2.3 本次使用上述独立输出目录，未覆盖运行中的旧版。首版未配置代码签名或自动更新。桌面冒烟截图与报告自 0.2.1 起按版本保存在 `var/desktop-smoke/<版本>/`；历史 fixture 报告仍在父目录。实际验证边界见 [VALIDATION.md](VALIDATION.md)。

Electron 首次启动会下载运行时，可提前运行 `pnpm --dir codex-resume install:electron`。启动脚本移除终端继承的 `ELECTRON_RUN_AS_NODE`，确保打开 GUI。

## CLI 三种验证模式

| 模式 | 额度与错误 | 发送及回执 | 结论边界 |
|---|---|---|---|
| simulation | 内存信号、虚拟时钟 | 内存目标 | 只证明状态机及边界行为 |
| hybrid | 注入受限错误及短等待窗口，到时读取真实额度 | 真实桌面原会话 | 证明等待、真实额度复查、单次发送及回执链路，不证明真实额度曾耗尽 |
| live | 桌面返回的真实错误与额度 | 真实桌面原会话 | 错误、受限快照、恢复快照和回执齐全，才记录真实闭环成功 |

```powershell
pnpm cli simulate --job var/demo.json
pnpm cli inspect --caller <本次授权会话ID>
pnpm cli hybrid --caller <本次授权会话ID> --target <已完成测试会话ID> --delay-ms 15000 --poll-ms 1000 --max-ms 90000
```

混合验证只能选择已完成且空闲的其他会话；它只要求模型回复唯一标记，不执行工具或修改旧项目。
混合验证的窗口和错误明确标注为 `injected`，证据文件不会将其记为真实恢复。
时间到了但真实五小时或每周额度仍耗尽时，程序继续等待，不发送。

## 登记与运行真实验证

```powershell
pnpm cli arm --caller <本次授权会话ID> --target <指定目标会话ID> --job var/my-task.json
pnpm cli run --job var/my-task.json --poll-ms 30000 --max-ms 21600000
pnpm cli status --job var/my-task.json
```

`arm` 仅登记，不发送消息；`run` 启动独立于模型的监控，最多运行指定时间。
登记时添加 `--follow-session` 可在正常结束后继续只读观察同一聊天，等待后续自然限额事件；不会续跑已完成轮次。
真实模式仅在指定会话最新一轮出现明确的服务端 `UsageLimitExceeded` 错误后等待并续跑。
普通完成、主动中断、非额度失败、人工恢复、目标变化、审批或输入等待不会自动触发续跑。
默认续跑同样只回复标记，以验证真实跨窗口链路。需要继续业务工作时，登记时显式添加 `--prompt-file <中文提示词文件>`。
业务提示词由用户定义，程序不会自行扩大任务目标；本项目只核验续跑轮次完成，不等同于业务总目标完成。

状态保存在 `var/*.json`，事件记录在同名 `.events.jsonl`。不要手工修改运行中作业的目标、提示词或状态。
同一目标在本项目中只允许一个监控实例；即便作业文件名不同也持有目标锁。
正常停止会释放锁；进程被强制终止后，确认原进程已退出再运行：

```powershell
pnpm cli unlock --job var/my-task.json
pnpm cli run --job var/my-task.json
```

发送前先持久化意图；发送超时或中途崩溃时不会盲目补发：

```powershell
pnpm cli reconcile --job var/my-task.json
pnpm cli status --job var/my-task.json
```

`reconcile` 仅核对投递标记和原会话回执，不会补发。仍不确定时保留 `send_uncertain`，交由用户核对。

## 当前限制

- 接口来自已验证的桌面内部命名管道，升级可能变化；程序会发现管道并核对工具目录和必要参数。
- 不读取 `auth.json`，不购买积分、不使用重置奖励，也不切换账号或 API 计费。
- 缺失额度值按未知处理；同时检查五小时和每周窗口，恢复时间之后仍需真实服务端复查。
- 多个桌面管道需要用户显式指定 `--pipe`；连接关闭后只读请求允许重新发现和重连。
- 当前使用 `read_thread` 轮询，不依赖此前外部调用失败的 `wait_threads`。
- 发送前的最后检查与桌面接收之间仍有极短的人工并发窗口；内部接口没有原子条件发送承诺。
- 支持等待状态保存及重启，但不自动安装系统服务或开机启动；桌面 App 和监控进程都需要运行。
- 真实额度未耗尽时，不人为烧额度来制造验证条件；最新实际结果见 `VALIDATION.md`。

## 文件入口

- `src/cli.ts`：命令行；`desktop.ts`：内部管道适配；`engine.ts`：监控状态机。
- `src/domain.ts`：额度、错误及投递身份判断；`store.ts`：持久化与互斥；`scenarios.ts`：明确标注的测试适配器。
- `test/engine.test.ts`：限额、人工干预、账号切换、发送不确定及持久化测试。
- `electron/`：主进程、预加载和监控进程；`renderer/`：Vue 界面；`src/app/`：应用契约、数据库、调度与会话索引引导。
- 项目约束和学习日志位于 `../.ai/projects/codex-resume/`。
